# Grok Bot 风格 UI 设计规范 V1.0

**定位：** AI Agent 智能助手应用  
**设计目标：** 高度接近 Grok Bot 的视觉风格、布局、组件和交互体验  
**适用平台：** Desktop Web / Windows / macOS / Mobile  
**设计基准：** 2026 年 10 月

---

## 01. 整体设计风格

### 核心视觉

采用极简、现代、轻量的设计语言。

关键词：

- Minimal / 极简
- Soft UI / 轻柔界面
- Neutral / 中性色
- Rounded / 圆润
- Spacious / 大面积留白
- Subtle Motion / 微动效
- Conversational / 对话式交互

视觉特征：

1. 整体以白色、近白色、浅灰色、黑色为基础。
2. 不使用大面积彩色背景或夸张渐变。
3. 通过留白、文字权重和层级组织信息。
4. 按钮、输入框和消息气泡采用较大的圆角。
5. 边框极浅，阴影柔和，尽量减弱容器的存在感。
6. 彩色主要来自 Bot 头像及少量状态反馈。
7. 界面要轻盈、安静、精致，避免传统后台系统那种厚重感。

**核心要求：宁愿减少装饰，也不要用视觉噪声填充空白。**

## 03. 字体系统

### 字体建议

英文字体：

`Inter, -apple-system, BlinkMacSystemFont, "SF Pro Text", sans-serif`

中文字体：

`PingFang SC, Noto Sans SC, Microsoft YaHei, sans-serif`

新版 Grok Bot 已经更换过字体，具体官方字体家族暂未确认。这里采用视觉接近的系统无衬线方案。

### 字号与字重

| 元素 | 字号 | 字重 | 行高 |
|---|---:|---:|---:|
| 页面大标题 | 28px | 600 | 1.25 |
| 页面标题 | 22px | 600 | 1.3 |
| Bot 名称 | 15px | 600 | 1.4 |
| 主聊天正文 | 15–16px | 400 | 1.55 |
| 普通按钮 | 14px | 500 | 1.4 |
| 侧边栏名称 | 14px | 500 | 1.4 |
| 侧边栏摘要 | 12–13px | 400 | 1.4 |
| 时间标签 | 12px | 400 | 1.4 |
| 辅助说明 | 12–13px | 400 | 1.5 |

文字默认左对齐。

减少全大写标题，不使用过粗或过密的字体。优先用轻微字重差异建立层级。

## 04. 页面布局系统

### Desktop 页面结构

默认以 `1440 × 900` 为设计基准。

整体采用三栏布局：

**左侧 Bot Sidebar + 中央 Chat Workspace + 可选右侧 Detail / Computer Panel**

| 区域 | 推荐尺寸 |
|---|---|
| 左侧边栏 | 280px |
| 顶部标题栏 | 56px |
| 主聊天区 | 剩余宽度自适应 |
| 聊天正文最大宽度 | 820px |
| 右侧详情面板 | 400px |
| 聊天区水平内边距 | 24–32px |
| 底部输入区域 | 自适应，最小 64px |

页面采用完整窗口布局，不要让整个 App 浮在一个带巨大圆角的外部容器里。

不同区域之间只用非常轻的分割线区分。

### 响应式规则

- `≥1200px`：完整侧边栏、聊天区、可展开右侧面板。
- `768–1199px`：侧边栏可收缩为头像导航栏，右侧面板使用覆盖模式。
- `<768px`：单栏聊天布局，Bot 列表作为独立页面或抽屉展示。

### 间距系统

采用 4px 基础网格。

常用数值：

`4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48px`

不要随意使用无规律的间距。

## 05. 左侧 Bot Sidebar

**这是 Grok Bot 风格最重要的结构之一。**

侧边栏应以 Bot 为组织中心，而非普通聊天历史记录。

### 顶部区域

包含：

- 产品标识
- 搜索入口
- 新建 Bot / 新建聊天入口
- 侧边栏展开或收起入口

顶部控件保持简洁，以线性图标为主。

### Bot 列表

每个 Bot 展示：

- 彩色头像
- Bot 名称
- 最近一条消息或工作摘要
- 相对时间
- 未读或需要处理的状态

建议参数：

| 属性 | 推荐值 |
|---|---|
| 列表项高度 | 64px |
| 头像尺寸 | 40px |
| 列表项圆角 | 12px |
| 水平内边距 | 12px |
| 头像与文字间距 | 12px |
| 名称字号 | 14px |
| 摘要字号 | 12px |

### 状态反馈

Bot 列表至少支持：

- Idle：正常静止
- Thinking：思考中
- Working：正在工作
- Waiting：等待用户输入
- Needs Attention：需要确认
- Done：已完成
- Unread：有未读结果

不同状态优先通过头像表情、轻微动态和简洁标记表达。

不要在每个 Bot 后面堆放大量标签。

### 列表交互

- Hover：背景由透明变为 `#F3F3F3`。
- Selected：使用稍深的中性色底面。
- Working：头像出现低频动态。
- Needs Attention：小型提示标记。
- 右键或更多菜单：重命名、置顶、移动分组、设置、删除。
- 支持分组折叠、拖动排序。

## 06. Bot 头像设计

Grok Bot 很鲜明的特征，是一套由简洁几何形状组成的彩色角色。

### 外观规则

头像可以使用：

- 圆形
- 圆角方形
- 水滴形
- 六边形
- 云朵形
- 不规则柔和几何形

每个头像主体使用一种鲜明纯色。

例如：

`#FF2D86 / #FF6900 / #0DBBA6 / #8051F4 / #1787F7 / #19BD76`

头像中央使用两个简单的白色椭圆、短线或胶囊状眼睛。

尽量避免鼻子、嘴巴和复杂的拟人化五官。

### 视觉约束

- 头像不使用照片。
- 不使用复杂 3D 渲染。
- 不使用真实材质和复杂纹理。
- 控制在小尺寸下仍然能清楚辨识。
- 全部 Bot 保持统一的几何和眼睛语言。

### 动态状态

- Idle：保持静止，偶尔眨眼。
- Thinking：眼睛轻微移动。
- Working：身体小幅摆动或旋转。
- Waiting：动作暂停，眼睛朝向一侧。
- Blocked：表情呈现疑惑。
- Done：短暂的完成反馈，然后回到 Idle。

头像是品牌体验的一部分，动效需要精致但不能喧宾夺主。

## 07. 顶部聊天标题栏

高度：`56px`

主要内容：

- Bot 头像
- Bot 名称
- Bot 当前状态
- 会话详情入口
- 电脑预览相关入口

标题栏背景与主画布一致。

不使用醒目的底部分割阴影。

点击 Bot 名称或头像，可以打开 Bot 详情面板。

状态标记、标题和操作按钮需保持视觉平衡。

## 08. Chat 聊天消息系统

### 基础聊天样式

聊天界面保持大面积白色背景。

Agent 消息：靠左显示。

用户消息：靠右显示。

时间信息弱化处理，不要让时间成为主要视觉元素。

### Agent 消息气泡

| 属性 | 推荐值 |
|---|---|
| 背景 | `#F5F5F5` |
| 文字 | `#151515` |
| 圆角 | 18px |
| 内边距 | 12px 16px |
| 最大宽度 | 主聊天区域的 76% |
| 阴影 | 默认无 |
| 边框 | 默认无 |

### 用户消息气泡

| 属性 | 推荐值 |
|---|---|
| 背景 | `#111111` |
| 文字 | `#FFFFFF` |
| 圆角 | 18px |
| 内边距 | 12px 16px |
| 最大宽度 | 主聊天区域的 76% |

### 消息间距

- 同一组消息之间：8px
- 不同轮次之间：20–24px
- 时间分隔标签上下：24px
- 消息与附件卡片之间：8px

内容需要自然流动，避免每条消息外面都套一层复杂卡片。

### 消息操作

Hover 消息时出现轻量操作：

复制、回复、表情反馈、更多操作。

不需要默认全部展开。

图片支持圆角预览，文件显示小型附件卡片。

## 09. Composer 底部输入框

Grok Bot 的输入框应当像即时通讯软件，圆润、紧凑、可自然扩展。

### 容器

- 默认背景：`#FFFFFF`
- 圆角：24–28px
- 边框：1px 极浅灰色
- 高度：48–52px，输入多行时自适应
- 文本内边距：12–16px
- 外部水平留白：16–24px
- 最大输入高度：200px

### 左侧

圆形 `+` 按钮，添加文件、图片或其他内容。

### 中间

输入区域，占位符：

`Message [Bot Name]`

或

`向 [Bot Name] 发送消息`

### 右侧

- 语音输入入口
- 发送按钮
- 正在生成时可切换为停止按钮

发送按钮使用黑色圆形，内置白色上箭头。

### 键盘规则

- Enter：发送
- Shift + Enter：换行
- Ctrl/Cmd + B：收起或展开侧边栏
- Ctrl/Cmd + K：全局搜索
- Esc：关闭当前弹层

输入框获得焦点时，仅做轻微边框强化，不使用发光效果。

## 10. Inline Widgets 聊天内交互组件

Grok Bot 的聊天内容可以直接包含用户可操作的 UI。

这是设计时需要重点保留的能力。

### 组件类型

- 单选或多选卡片
- 邮件预览
- 待确认操作
- 文件卡片
- 工作结果卡片
- 定时任务卡片
- 工具执行事件
- 数据图表
- 简洁表单

### 卡片样式

建议：

- 卡片背景：白色或浅灰色
- 边框：1px `#E8E8E8`
- 圆角：14–16px
- 内边距：16px
- 操作项高度：44–48px
- 操作项之间通过浅色分割线区分

主操作按钮使用黑底白字，次要操作使用浅灰背景或纯文字。

### 交互要求

用户在聊天中可以直接：

- 勾选选项
- 确认或拒绝操作
- 查看任务详情
- 预览文件
- 修改计划
- 点击发送邮件

尽量不要把这些操作转换成独立的复杂后台页面。

## 11. 工作过程和任务状态

Bot 的工作过程采用渐进展示方式。

### 默认状态

主要显示：

- Bot 头像动态
- 简短工作状态
- 必要的进度描述

例如：

`正在搜索网页...`

`正在读取文件...`

`正在整理结果...`

### 详细状态

用户点击或悬停时，才展示更多执行过程。

例如：

- 已打开浏览器
- 已读取 3 份文档
- 已生成报告
- 等待授权

展示时使用小型文字行、折叠区块和弱化图标。

不要始终展开完整日志，也不要让动画或滚动日志抢占阅读空间。

### 任务完成

显示完成结果，并保留后续操作入口。

需要用户处理的问题用简洁卡片呈现。

## 12. 右侧 Bot 详情与电脑预览

### 默认行为

右侧面板默认关闭。

用户主动打开 Bot 详情或电脑预览后显示。

### 面板尺寸

推荐宽度：`380–420px`

内部包含：

- Bot 基础信息
- 运行状态
- 电脑预览
- 文件与结果
- Routines
- Bot 设置

### 电脑使用体验

区分三个层级：

**Status**

使用简洁状态图标说明电脑是否在运行。运行中可显示紫色。

**Preview**

右侧展开电脑预览，保持聊天区可见。

**Takeover**

用户需要操作时，将电脑预览放大至全屏或主要工作区域，并提供明确的交还控制按钮。

### 电脑预览外观

窗口背景以中性色为主。

可以使用极柔和的灰色抽象壁纸，并随时间产生细微变化。

避免默认展示过多电脑控制按钮。

---

## 13. Routines 定时任务界面

Routines 属于 Bot 的长期能力，应与当前 Bot 保持关联。

### 列表项

展示：

- Routine 名称
- 执行时间或触发条件
- 启用状态
- 最近执行结果

### 视觉参数

- 卡片圆角：14px
- 卡片间距：8–12px
- 内边距：16px
- 标题字号：14px
- 描述字号：12px

支持启用、暂停、编辑和查看记录。

Routine 执行时，相关事件也可以直接出现在聊天时间线中。

## 14. 按钮、圆角与阴影系统

### 圆角 Token

| 类型 | 值 |
|---|---|
| 小型按钮 | 8px |
| 普通菜单项 | 10px |
| 侧边栏列表项 | 12px |
| 普通卡片 | 14px |
| 消息气泡 | 18px |
| 输入框 | 26px |
| 胶囊按钮 | 999px |

### 按钮

Primary：黑色背景、白色文字。

Secondary：浅灰背景、深色文字。

Ghost：透明背景，悬停时出现浅灰底色。

Destructive：危险操作使用红色文字。

### 阴影

常规消息气泡不使用阴影。

悬浮按钮和弹层可以使用：

`0 4px 20px rgba(0,0,0,0.04)`

悬浮面板可以使用：

`0 12px 32px rgba(0,0,0,0.08)`

禁止使用明显的蓝色外发光、厚重投影或拟物高光。

---

## 15. 图标系统

推荐使用 Lucide 风格的线性图标。

建议规格：

- 图标尺寸：16 / 18 / 20 / 24px
- 描边宽度：1.75–2px
- 描边端点：Round
- 默认颜色：`#424242`
- 次要颜色：`#A0A0A0`

统一使用简洁的轮廓图标。

不要在同一个界面混用三种不同图标库。

图标按钮建议最小可点击范围为 40px；移动端优先 44px。

---

## 16. 交互动效规范

整体动效遵循轻、短、自然的原则。

| 场景 | 时间 | 推荐曲线 |
|---|---|---|
| 按钮悬停 | 120ms | ease-out |
| 列表选中 | 160ms | ease-out |
| 弹出菜单 | 180ms | ease-out |
| 侧边栏展开 | 220ms | ease-in-out |
| 右侧面板展开 | 240ms | ease-in-out |
| 消息进入 | 180ms | ease-out |
| 头像状态切换 | 250ms | ease-in-out |

### 细节限制

- 禁止大幅度弹跳。
- 禁止频繁的缩放和旋转。
- Hover 不需要每次都放大按钮。
- 消息进入时最多使用 4–8px 的轻微位移。
- 工作中头像动效应低频、平滑。
- 支持 `prefers-reduced-motion`。

交互反馈要让用户感觉界面很灵敏，但不能让人意识到每个控件都在刻意表演。

## 17. Mobile 移动端设计

移动端保留桌面版的基础视觉语言。

### 顶部导航

- 左侧：返回按钮
- 中间或偏左：Bot 头像及名称
- 右侧：电脑预览或更多操作

导航按钮使用圆形或胶囊形浅色容器。

### 聊天区

- 背景：近白色
- 左右边距：16–20px
- 消息最大宽度：约 82–88%
- 消息正文：16px
- 消息气泡圆角：18px

### 底部输入框

采用贴近屏幕底部的悬浮胶囊式布局。

左侧为独立 `+` 按钮，右侧为语音或发送按钮。

必须适配键盘弹出、安全区域和输入框多行增长。

### Bot 列表

移动端使用独立列表页面，不强制展示永久侧边栏。

优先保留头像、名称、最近工作摘要和状态。

---

## 18. 空白页与新建 Bot

新建 Bot 页面尽量减少表单感。

初始界面可以只包含：

- 一个醒目的 Bot 头像
- 一句简洁的欢迎标题
- 一段简短描述
- 一个主要操作按钮
- 少量建议选项

页面使用大量留白，视觉焦点集中在头像和操作按钮。

不需要展示大量配置字段。

创建 Bot 后，更多名称、描述、权限、工具和设置可以逐步提供。

---

## 19. 性能与体验约束

视觉设计必须兼顾响应速度。

- 侧边栏切换应尽量即时。
- 输入框在页面加载后应尽早可用。
- 列表较长时采用虚拟滚动。
- 复杂聊天卡片按需加载。
- 聊天滚动不应因为新消息出现而突然跳动。
- 右侧面板展开不得破坏当前滚动位置。
- 工作状态只更新相关组件，避免整页重绘。
- 加载状态保持低干扰。
- 所有重要操作保留键盘支持和可见焦点。

## 20. 最终设计验收标准

### 视觉

- [ ] 以黑白灰和留白为核心
- [ ] 没有多余渐变、彩色背景和厚阴影
- [ ] 头像采用统一的彩色几何语言
- [ ] 消息气泡、输入框、菜单具有统一圆润风格
- [ ] 文字大小、字重、行高一致
- [ ] 暗色模式具有完整对应关系

### 结构

- [ ] 左侧以 Bot 名单为中心
- [ ] 中央为主要聊天画布
- [ ] 右侧详情默认隐藏
- [ ] 电脑预览可在需要时展开
- [ ] 聊天支持嵌入交互卡片
- [ ] Routine 和任务状态可以融入对话

### 交互

- [ ] Hover、Focus、Active、Disabled 状态完整
- [ ] 状态变化具有轻微动效
- [ ] Bot 工作状态清晰
- [ ] 操作可撤销或可确认的场景具有反馈
- [ ] 侧边栏和弹层支持键盘操作
- [ ] 移动端适配完整

### 一致性

所有页面必须使用相同的 Design Tokens。

不允许某个页面突然换成传统 Dashboard 风格。

不允许为了突出功能而加入大量彩色按钮、复杂图表和装饰性容器。

**最终目标：打开应用后，用户应当立即感受到 Grok Bot 式的简洁、圆润、克制和即时通讯体验。功能可以复杂，界面必须保持轻盈。**
